# Неаполис — Солнечный анализ

**Версия 0.2.0.** Windows-приложение для интерактивного предварительного анализа прямого солнца по IFC-моделям. Интерфейс на русском языке, обработка IFC и расчёт выполняются локально. Интернет для работы не нужен.

## Возможности

- Импорт IFC2x3 и IFC4 до 300 МБ.
- Проверка координат, истинного севера и размеров модели.
- Множественное выделение окон через Ctrl + щелчок в 3D и в списке (Command на macOS).
- Расчёт выделенной группы или всех сохранённых внешних точек окон и фасадов.
- Полупрозрачная вертикальная плоскость текущего луча и суточная 3D-траектория солнца для активной точки.
- Построение горизонтальной сетки внутри контура площадки.
- Суммарные и непрерывные солнечные интервалы, шаг 1/2/5 минут.
- Временная шкала, луч к солнцу, выделение препятствия с IFC ID.
- Выгрузка CSV, сохранение и загрузка точек и параметров в JSON.

## Запуск Windows-версии

Windows 10/11, x64. Можно запустить `Neapolis-Solar-0.2.0-Portable.exe` без установки, установить приложение через `Neapolis-Solar-0.2.0-Setup-x64.exe` или распаковать весь ZIP и открыть `Neapolis Solar.exe`. Установщик собирается в Windows/GitHub Actions; локально в Linux проверена сборка Portable. Переносимый вариант при запуске распаковывает необходимые файлы во временный каталог. В систему не устанавливается, но Electron хранит свои пользовательские данные и кеш в профиле пользователя.

Файлы в этой ранней версии не подписаны сертификатом издателя. Реальный запуск на Windows ещё не проверен: сборка выполнялась в Linux. Пройдены вычислительные тесты, проверки локальной загрузки файлов и структуры Windows-пакета.

## Сборка из исходников

Нужны Node.js 24 и npm. В Windows PowerShell:

```powershell
npm ci
npm test
npm run test:desktop
npm start
```

Создание всех Windows-пакетов (Portable EXE, установщик NSIS, ZIP) на Windows:

```powershell
npm run package:win
```

Готовые EXE и ZIP появятся в `release/`. Только Portable можно собрать командой `npm run package:portable`. GitHub Actions автоматически проверяет и собирает Windows-пакеты при изменении `main`, в pull request к `main` и по тегам `v*`; доступен ручной запуск (`Windows application → Run workflow`). Результаты и `SHA256SUMS.txt` сохраняются как артефакт `Neapolis-Solar-Windows-x64`, без автоматической публикации Release. Подробности: [сборка и запуск в Windows](docs/WINDOWS.md).

Сырой IFC, чертежи, пользовательские модели, готовая геометрия демонстрационного ЖК и настройки хостинга не входят в исходники. При запуске самостоятельно собранной программы выберите свой IFC через кнопку импорта. Если в локальный `dist/model/` добавить подготовленный набор `model.json.gz` и `geometry-*.bin.gz`, программа откроет его автоматически. Личные данные добавлять в Git не нужно.

Подготовить модель локально:

```powershell
npm run build
node tools/prepare-model.mjs "C:\Models\Building.ifc" dist/model
```

После этого можно запускать программу или собирать её с этой моделью.

## Использование

1. Проверьте широту, долготу и UTC-смещение. Север задаётся по часовой стрелке от исходной оси IFC +Y; вращение камеры не меняет север.
2. Инструмент «Размер» измеряет расстояние между двумя выбранными точками. При необходимости исправьте масштаб, затем подтвердите север и размеры.
3. Нажмите «Окно / точка» и выберите внешнюю поверхность. Точка создаётся **в месте нажатия** с отступом 2 см наружу. Автоматически распознаются IfcWindow и объекты с именами О-* / Б-*; остальные поверхности можно выбирать вручную.
4. Для площадки задайте отметку и шаг сетки, перейдите к плану, обведите простой контур без пересечений и завершите построение. До 1000 точек.
5. Выберите дату и шаг времени. Ctrl + щелчок добавляет окно к выделению или снимает его. Обычный щелчок заменяет выделение. Точки остаются в списке; выделение и список расчётных точек — разные вещи. «Рассчитать выделенные» обрабатывает текущую группу, «Рассчитать все точки» — весь список. Каждый запуск заменяет предыдущие результаты; CSV содержит только текущий запуск. После расчёта выберите точку и время: жёлтый луч означает открытое солнце, красный заканчивается на препятствии.
6. «Плоскость луча» показывает вертикальное сечение через активную точку в текущем азимуте солнца; при перемещении времени оно поворачивается. «Суточная траектория» — направления на солнце над геометрическим горизонтом на выбранную дату. Цвет активной рамки — золотой, остальных выделенных окон — голубой. Все дневные лучи в общем случае не лежат в одной плоскости. Обе визуализации отключаются флажками под сценой.
7. Скачайте CSV или JSON с настройками. JSON проверяет имя модели, её габариты, первый GUID и масштаб; это проверка совместимости, не хеш всего IFC. При смене геометрии следует создать новые точки. В JSON также сохраняется выделение; файлы версии 0.1 поддерживаются. После загрузки JSON требуется новый расчёт.

## Метод и ограничения

Положение солнца рассчитывает SunCalc **1.9.0**. Местное время задаётся фиксированным смещением UTC, не зависит от часового пояса компьютера; автоматического перехода на летнее время нет. Расчётная система Three.js: X = IFC X, Y = IFC Z, Z = −IFC Y. Сцена смещается к центру здания для устойчивости вычислений.

Трассировка по треугольной геометрии использует MeshBVH. Проверяется центр солнца выше геометрического горизонта, лицевая полусфера выбранной поверхности и отсутствие непрозрачного препятствия. Материалы с alpha < 0.95 исключаются из препятствий, рамы сохраняются. Неправильно экспортированное непрозрачное стекло может затенять луч.

Продолжительность оценивается по серединам временных шагов; короткие интервалы могут быть пропущены. Проверка текущего времени выполняется отдельно, поэтому у границ интервалов возможны отличия от дискретной шкалы.

Это **предварительный анализ внешних точек**, а не нормативный расчёт инсоляции помещений или заключение о соответствии. Не реализованы нормативные точки и световые углы помещений, оценка квартир, КЕО, отражения, облачность и сезонная прозрачность деревьев. Окружение учитывается только при наличии в IFC. Порог 2 часа в сводке площадки — диагностический; доля солнечных точек не является точной долей её площади.

IFC-движок может сообщать о некорректных BREP-поверхностях. Такие модели требуют визуальной проверки полноты деталей. Проверка координат нескольких элементов не доказывает полноту всей геометрии.

## Устройство проекта

- `src/` — интерфейс и расчётные Web Workers.
- `desktop/main.cjs` — окно Electron, меню, локальные загрузки.
- `desktop/server.cjs` — загрузка ресурсов только через loopback с закрытым случайным маршрутом.
- `tools/prepare-model.mjs` — подготовка сжатого набора из IFC.
- `tests.mjs`, `desktop/server.test.cjs` — вычислительные и desktop-проверки.
- `.github/workflows/windows.yml` — Windows-сборка.

Renderer работает без Node.js, с context isolation и sandbox. Внешние сетевые запросы и навигация блокируются. Сохранение результатов открывает системный диалог выбора пути.

Лицензии сторонних библиотек приведены в `THIRD_PARTY_NOTICES.txt`. Исходный код проекта пока не имеет отдельной открытой лицензии.
